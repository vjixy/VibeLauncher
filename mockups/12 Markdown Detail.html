# Local RAG — design sketch
_Draft · Alex · 2026-04-19_

## Why local
Cloud RAG is **overkill** for a single-user launcher. Keeping the index on disk means:

- zero network round trips for search
- privacy by default (nothing leaves the box)
- works offline on the train

## Shape
A small HTTP service that speaks MCP, backed by sqlite-vss and a local embedding model. The launcher talks to it over http://localhost:8787/mcp.

## Tools surface
Start with four, add more once they earn their place:

1. `search_docs` — top-k semantic search
2. `index_document` — add file or text blob
3. `list_collections` — enumerate collections
4. `delete_document` — remove by id

## Risks
- Embedding model cold start (~600ms on M-series, worse on older Intel).
- Index fragmentation after heavy deletes; schedule a nightly VACUUM.
- Scope creep: resist adding a rerank tool until we can measure.
